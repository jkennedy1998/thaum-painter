### 2026-11-09-detailer-one-stroke-many-cells
- j-quote: "it needs to work so the user can draw across multiple cells potentially effecting them. might be over authored cells or over blank cells. needs to work with..."
- interpretation: One detailer drag is one action across many cells. Each cell the pointer crosses gets its own comparison buffer, seeded the moment the drag enters it (authored glyph tile, or blank tile for an additive crossing — subtract stays a no-op on empty cells). Re-crossing a cell continues its live buffer instead of reseeding; the add/erase mode is captured at press so a mid-stroke flip applies from the next stroke onward. Release commits only the buffers that actually moved ink, as one staged multi-cell action (one undo record). Brush size scales down into each buffer as a centered square footprint.

### 2026-11-09-detailer-additive-never-resolves-blank
- j-quote: "didnt work. i notice logs print things, but idont see any authored changes from using this tool"
- interpretation: The GUI resolved every additive stroke to the blank space glyph (the blank tile is the nearest neighbor of any sparse hand mark), so commits fired (131 cells of ' ') while the canvas looked untouched. Additive resolve must exclude the blank candidate and snap to the nearest INKED glyph — the sparsest mark lands on the smallest glyph (a dot), more ink lands on bigger glyphs. Subtractive keeps the blank candidate (a full erase is a valid result). A resolve landing back on the cell's own authored glyph stages no write at all (no-op guard), and live previews only show buffers whose ink actually moved.

### 2026-11-09-detailer-shape-differentiated-segments
- j-quote: "i notice that we now draw everywhere, but its the same glyph. we need to be able to draw a small shape / build up some shapes in the cells authoring with the detailer, and different cells should... drawing a line through full cell graphics should produce a visible slight negative line in the authored glyphs (not full negative)."
- interpretation: Every cell resolving to the same glyph had two roots, both fixed: (1) sparse un-interpolated marks are shapeless, so they all snap to the same smallest glyph — consecutive drag samples are now Bresenham-interpolated with the brush footprint at every step, so each crossed cell deposits its own stroke segment (vertical bar, arc piece) and resolves to the glyph nearest that segment; (2) a stroke whose ink moved could still snap back to the cell's seed glyph (nearest-neighbor to "full block minus a line" is the full block), which made subtractive negatives invisible — the seed glyph is now barred from winning the resolve on both lanes, so any visible edit lands on a different glyph (the slight-negative representation), while a buffer that ends exactly at its seed commits nothing (visible-change gate compares the buffer to its stored seed alpha).
